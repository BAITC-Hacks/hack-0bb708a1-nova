# EventMatch — подбор подрядчиков для мероприятий

Разговорный AI-координатор для хакатона: понимает запрос на русском за несколько сообщений, уточняет недостающие детали, подтверждает условия и показывает до трёх карточек. Под ним работает неизменный детерминированный подбор по 66 профилям. Форма и фиксированные демо сохранены в отдельной вкладке и работают без API.

## Запуск

Python 3.10+ (проверено на Python 3.14.2).

```bash
cd hack-0bb708a1-nova
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Открыть http://localhost:8501. Если терминал уже находится в папке репозитория, первую команду пропустить. В подготовленном рабочем окружении `.venv` уже создано, зависимости установлены.

Для чата нужен `OPENAI_API_KEY` в локальном `.env` рядом с `app.py` или в переменной окружения. Приложение загружает этот файл через `python-dotenv`. Не копируйте его в код. Пример настроек без секрета — `.env.example`:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
```

Переменные окружения имеют приоритет; после смены настроек перезапустите сервер. Используется официальный endpoint `https://api.openai.com/v1` и Responses API со строгой Pydantic-схемой. Ключ не передаётся в браузер или промпты; `.env` и его варианты исключены из Git. По умолчанию используется `gpt-4.1-mini`, проверенный с предоставленным ключом. Другую совместимую модель можно задать через `OPENAI_MODEL`.

Установка через `requirements.txt` устанавливает пакет из `src/` в editable-режиме и зависимости для тестов. После этого из корня репозитория работают обычные команды, без `PYTHONPATH`:

```bash
pytest
pytest tests/unit/test_matcher.py
python scripts/demo.py
```

Данные и `.env` остаются в корне checkout, вне пакета. Этот проект запускается из checkout с editable-установкой; отдельная wheel-поставка с каталогом не предусмотрена.

Отдельная **платная проверка реального API**, которая не запускается в unit-тестах:

```bash
python scripts/eval_live.py
# Или отдельная группа:
python scripts/eval_live.py --suite safety
python scripts/eval_live.py --suite multiturn
```

## Подбор в чате

При открытии активна вкладка «Подбор в чате». Пример демонстрации:

1. «Нужен ведущий на свадьбу в Алматы 2 ноября 2026 года, до 2 млн тенге, на 6 часов, на русском».
2. Проверить резюме и ответить «да» или нажать «Найти подрядчиков». Результаты и оценки совпадают с прежним подбором.
3. «А подешевле?» — EventMatch уточнит новый потолок бюджета, не изменяя его наугад.
4. «До 800 тысяч, дату оставим» — новое резюме, затем подтверждение и новый поиск.
5. «А на другую дату?» → «15 ноября 2026» — остальные условия сохраняются.
6. «Напиши рецепт борща» или просьба обойти фильтры — краткий возврат к задаче, без вызова matcher.

Можно начать с «Ищу фотографа в Астане» и добавить дату, формат и бюджет позже. Год не угадывается. Несколько дат/городов/категорий, другая валюта и расплывчатый бюджет требуют уточнения. Суммы без указания валюты понимаются как тенге в контексте сервиса. «Язык не важен» снимает предпочтение; язык и часы не обязательны для поиска.

Для нового события нажмите «Новый поиск» в боковой панели — это очищает историю и условия текущей сессии. «Начать заново» в чате сбрасывает условия, сохраняя отображаемый разговор. У каждой выдачи в истории остаются её собственные условия; новая правка не меняет старые карточки.

## Интерфейс и календарь

Основная вкладка — **«Подбор в чате»**, резервная — **«Поиск по параметрам»**. Поле «Локация» соответствует внутреннему `city`: Алматы, Астана или Зарубежье. Карточки показывают имя, категорию и локацию, начальную цену, объяснение и дополнительные сведения. Синтетические профили отмечены; `price_imputed` отображается как «Ориентировочная цена», `city_imputed` — «Локация указана ориентировочно». Обычный интерфейс не показывает оценки, сценарии или статистику. В боковой панели — «Новый поиск», «О сервисе» и простое объяснение «Как работает подбор». Цвета, размеры заголовков и границы настроены штатной темой `.streamlit/config.toml`; небольшой CSS убирает аватары и ограничивает ширину чтения. Подтверждение — короткое резюме без технических названий полей. Необязательные язык и длительность не задерживают поиск.

Проверка доступности поддерживается только **23.09.2026–31.12.2026 включительно**. Форма ограничивает календарь этим периодом и дополнительно проверяет дату перед вызовом подбора. Чат проверяет извлечённую дату, просит выбрать дату внутри диапазона и блокирует подтверждение, пока это не исправлено. Подтверждение повторно проверяет период, чтобы старый черновик или открытая вкладка не обходили ограничение. Остальные условия сохраняются. Дата не переносится автоматически на границу периода. Эти проверки находятся вне `matcher.py`; прямой низкоуровневый вызов matcher сохраняет прежнее поведение.

## Архитектура

**LLM understands the request; deterministic code decides the recommendation.**
LLM понимает запрос; детерминированный код решает, кого рекомендовать.

```text
app.py                         # композиция страницы и внедрение backend
src/eventmatch/
├── __init__.py
├── paths.py                   # пути checkout, .env и NOVA_DATASET
├── domain/
│   └── matcher.py             # Request, Contractor, каталог, фильтры, рейтинг
├── application/
│   ├── conversation.py        # состояние, уточнения, подтверждение, поиск
│   ├── availability.py        # политика поддерживаемых дат
│   └── presentation.py        # текст резюме и исходов
├── ai/
│   ├── models.py              # схемы ответов и общий AgentError
│   └── prompts.py             # контракт извлечения и объяснений
├── infrastructure/
│   └── openai_client.py       # SDK, .env, тайм-ауты, безопасные ошибки
└── ui/
    ├── chat.py, manual.py     # чат и резервный ручной поиск
    ├── components.py          # карточки и отображение текста
    ├── state.py               # инициализация и сброс состояния UI
    └── demo_scenarios.py      # четыре фиксированных запроса
scripts/
├── demo.py                    # CLI тех же сценариев
└── eval_live.py               # только явный запуск платных проверок
tests/                       # pytest; без обращений к реальному API
├── support.py                 # общие фикстуры
├── unit/                      # matcher, conversation, availability
└── integration/               # UI, mocked API, границы пакетов, пути
data/                        # исходный CSV без изменений
pyproject.toml                 # пакет, зависимости и обнаружение тестов
requirements.txt               # editable-установка с test-зависимостями
```

Каждая директория пакета содержит пустой `__init__.py`; реэкспортов и модификаций `sys.path` нет. `Request` и `Contractor` оставлены в matcher: отдельный файл моделей здесь не улучшает границы.

```text
Пользователь → app.py → Streamlit UI
                           ├── чат → application.conversation
                           │           ├── внедрённый infrastructure.openai_client
                           │           │       → OpenAI → ai.models → проверенные изменения
                           │           └── валидация → подтверждение → domain.matcher
                           └── ручная форма → валидация → domain.matcher
                                                           ↓
                                   Top-3 / CATEGORY_NOT_FOUND / NO_MATCH
                                                           ↓
                         application.presentation + отдельные AI-объяснения
                                                           ↓
                                               ui.components → карточки
```

Направление импортов: UI → application → domain. Application также использует provider-independent `ai.models`; backend передаётся из `app.py`, без импорта SDK или инфраструктуры в application. Infrastructure зависит от AI-контракта и общих путей. Только infrastructure импортирует OpenAI и загружает `.env`. Domain использует только стандартную библиотеку. Архитектурные тесты проверяют запрещённые зависимости и циклы.

Жизненный цикл разговора: сбор обязательных полей → уточнение или подтверждение → одноразовый поиск → результаты → исправление → новое подтверждение. `Conversation` хранится только в `st.session_state`; функции UI-состояния принимают mapping. Сброс чата не изменяет ручную форму. История ограничена 80 сообщениями, контекст модели — 12 репликами, кэш объяснений — 20 выдачами. На диск состояние не записывается.

LLM возвращает изменения с точными цитатами текущего сообщения. Application проверяет схему, цитаты, числа и даты; неоднозначность блокирует поиск. Общая политика `application.availability` используется и в чате, и в ручной форме. Повторная проверка перед поиском защищает от устаревшего подтверждения.

Факты выбора в `Conversation.last_result` и `Message.result` остаются неизменными. Адаптер получает копию только выбранных профилей без полных календарей и истории. Проверенные формулировки хранятся отдельно в `Message.explanations` по ID; неизвестные ID игнорируются. Дословная цитата профиля и отдельный LLM-вызов проверяют обоснованность текста. При ошибке UI показывает короткое детерминированное объяснение из даты, начальной цены и точной цитаты профиля; отсутствие выбранного языка явно отмечается. Полное исходное объяснение matcher сохраняется в результате без изменений. Проверка формулировок вероятностная, но состав, порядок, баллы и причины отказа всегда определяет Python.

Посторонние, опасные и атакующие сообщения не меняют запрос и не запускают matcher; явные попытки обхода правил дополнительно отсеиваются локально. Текст экранируется при отображении. Один ход обычно требует одного API-вызова; успешный поиск — ещё двух для объяснений и проверки. Для пустых исходов генерация не нужна. Тайм-аут — 25 секунд, автоматических повторов нет, `store=False`. Ошибки провайдера преобразуются в безопасный `AgentError`, а ручной поиск остаётся доступным.

## Каталог и особенности разбора

Фактическое имя полученного файла — `data/hackathon dataset anonymized .csv` (с пробелами). Файл не изменён. Для другого расположения задать `NOVA_DATASET` перед запуском; поддерживаются CSV и JSON-массив объектов той же схемы.

- 66 уникальных профилей: 53 исходных и 13 синтетических, уже присутствующих в датасете. Дополнительные профили не добавлены.
- В `categories`, `event_formats`, `languages`, `busy_dates` значения разделены `|`. Категорий у профиля может быть несколько. Также поддерживаются JSON-массивы.
- `True`/`False` преобразуются явно: строка `False` не становится истинным значением.
- Девять пустых `max_hours` преобразуются в `None`: ограничение по продолжительности неприменимо. При указанной продолжительности такой профиль не исключается.
- Восемь профилей имеют `city_imputed`, 18 — `price_imputed`. Эти признаки показаны на карточках; восстановленные значения используются как значения каталога.
- Городские значения: Алматы, Астана, Зарубежье. Последнее сохранено как есть; описания не используются для расширения географии.
- Даты занятости: ISO `YYYY-MM-DD`, в предоставленном файле — с 23.09.2026 по 31.12.2026. Внутри этого периода отсутствие даты в `busy_dates` означает доступность **по данным каталога**; внешнего подтверждения нет. Даты за пределами периода не допускаются интерфейсом и контроллером разговора.
- `price_from_kzt` — начальная цена, а не почасовой тариф или окончательная смета. Фильтр сравнивает её с бюджетом, не умножает на часы и не придумывает доплаты. Карточки показывают «от»; точную стоимость из этого датасета установить нельзя.
- Неполные обязательные поля, дубликаты ID, некорректные даты, числа и флаги вызывают понятную ошибку с номером профиля. Некорректные ограничения не заменяются на «свободен» или нулевую цену.

## Пайплайн

`matcher.py` не зависит от Streamlit и не делает сетевых запросов.

1. `filter_candidates`: точное совпадение города и категории после нормализации регистра, пробелов и `ё/е`; затем дата, поддерживаемый формат, начальная цена ≤ бюджет и `max_hours ≥ duration`, если оба значения применимы.
2. `rank_candidates`: вычисляет прозрачные составляющие оценки только для прошедших фильтры кандидатов.
3. `recommend`: сортирует по убыванию полной оценки, затем по строковому ID по возрастанию; округление применяется только после сортировки. Возвращает максимум три карточки. При одинаковом каталоге и запросе результат не зависит от порядка строк, времени или случайности.
4. `explain`: составляет объяснение из имени, города, категории, даты, цены, формата, часов, языка и дословного фрагмента описания. LLM не используется, новые факты не генерируются.

| Сигнал | Баллы | Правило |
| --- | ---: | --- |
| Формат | 20 | У всех прошедших фильтр формат поддерживается; это фиксированная составляющая |
| Язык | 0 или 30 | 30 при совпадении; если предпочтение не задано, 30 у всех |
| Бюджет | 0–15 | `15 × max(0, 1 − abs(цена / бюджет − 0.75) / 0.75)` |
| Продолжительность | 10–15 | `10 + 5 × min((max_hours − часы) / часы, 1)`; при отсутствии ограничения или запроса — 15 |
| Описание | 0–20 | `20 × cosine(TF-IDF(запрос), TF-IDF(описание))` |

Бюджетная составляющая предпочитает начальную цену около 75% бюджета, оставляя резерв. Это демонстрационная эвристика, а не оценка качества услуги: самый дешёвый подрядчик не получает автоматического преимущества. Язык — мягкое предпочтение, несовпадение явно отмечается в объяснении.

TF-IDF рассчитывается по всему каталогу: `idf = log((1 + N) / (1 + df)) + 1`, TF — число вхождений. Запрос состоит из категории, формата и выбранного языка. Токенизация локальная, без стемминга и словаря синонимов: это простая лексическая близость, поэтому разные формы русского слова могут не совпасть. Максимум — 100 баллов; это соответствие запросу, не рейтинг качества подрядчика.

В ответе `recommend` есть `status`, `message`, `cards`, `rejections`, `city_category_count`, `eligible_count`. Карточка содержит объект `Contractor`, `score`, `score_parts`, `explanation`.

- `SUCCESS`: есть подходящие профили; если их меньше трёх, сообщение объясняет это.
- `CATEGORY_NOT_FOUND`: в выбранном городе нет нужной категории.
- `NO_MATCH`: категория в городе есть, но все профили отсеяны. Причины считаются независимо; один профиль может нарушить несколько условий, поэтому сумма причин может превышать число профилей.

## Демонстрация

Для судей открыть `http://localhost:8501/?review=1`. Этот параметр включает только дополнительные элементы отображения, не меняет подбор и не является контролем доступа. Во вкладке «Поиск по параметрам» раскрыть **«Примеры поиска»**, выбрать сценарий и нажать **«Найти подрядчиков»**. Значения можно менять; изменение ввода убирает старые результаты формы.

| Сценарий | Город, дата, формат | Категория и условия | Ожидаемый результат |
| --- | --- | --- | --- |
| Плотная категория | Алматы, 02.11.2026, свадьба | Ведущий; 2 000 000 ₸; 6 ч; русский | 4 подходят; показаны Сон Гоку, Хаул, Эмилия |
| Редкая категория | Алматы, 14.11.2026, свадьба | Флорист; 400 000 ₸; без часов; русский | 1 карточка: Тихиро Огино, пометка «Синтетический профиль» |
| Нет подходящих вариантов | Алматы, 14.11.2026, свадьба | Ведущий; 1 000 ₸; 6 ч; русский | 5 заняты, 4 не поддерживают формат, у 10 начальная цена выше бюджета |
| Нет категории в локации | Астана, 14.11.2026, свадьба | Декоратор; 400 000 ₸ | Категория отсутствует в городе |

В режиме `?review=1` под результатами раскройте **«Подробности подбора»**, чтобы показать составляющие оценки судьям. Округление до одного знака применяется только к отображению; исходные баллы и порядок неизменны. CLI `scripts/demo.py` воспроизводит те же запросы.

Тон и примеры кратких уточнений заданы в инструкциях модели, как описано в [OpenAI Docs: Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering).

Интеграция следует [официальной документации OpenAI по Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). При переносе в пакет алгоритмы `domain/matcher.py`, промпты и исходный CSV не изменены.
