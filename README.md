# Nova — подбор подрядчиков для мероприятий

Разговорный AI-координатор для хакатона: понимает запрос на русском за несколько сообщений, уточняет недостающие детали, подтверждает условия и показывает до трёх карточек. Под ним работает неизменный детерминированный подбор по 66 профилям. Форма и фиксированные демо сохранены в отдельной вкладке и работают без API.

## Запуск

Python 3.10+ (проверено на Python 3.14.2).

```bash
cd hack-0bb708a1-nova
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

Открыть http://localhost:8501. Если терминал уже находится в папке репозитория, первую команду пропустить. В подготовленном рабочем окружении `.venv` уже создано, зависимости установлены.

Для чата нужен `OPENAI_API_KEY` в локальном `.env` рядом с `app.py` или в переменной окружения. Предоставленный ключ уже находится в `.env`; приложение загружает его через `python-dotenv`. Не копируйте его в код. Пример настроек без секрета — `.env.example`:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
```

Переменные окружения имеют приоритет; после смены настроек перезапустите сервер. Используется официальный endpoint `https://api.openai.com/v1` и Responses API со строгой Pydantic-схемой. Ключ не передаётся в браузер или промпты; `.env` и его варианты исключены из Git. По умолчанию используется `gpt-4.1-mini`, проверенный с предоставленным ключом. Другую совместимую модель можно задать через `OPENAI_MODEL`.

Проверка логики и сценариев без установки Streamlit:

```bash
python3 -m unittest -v test_matcher
python3 demo.py
```

Все тесты, включая UI:

```bash
.venv/bin/python -m unittest -v
```

Отдельная **платная проверка реального API**, которая не запускается в unit-тестах:

```bash
.venv/bin/python eval_live.py
# Или отдельная группа:
.venv/bin/python eval_live.py --suite safety
.venv/bin/python eval_live.py --suite multiturn
```

## Разговор с Nova

При открытии активна вкладка «Разговор с Nova». Пример демонстрации:

1. «Нужен ведущий на свадьбу в Алматы 2 ноября 2026 года, до 2 млн тенге, на 6 часов, на русском».
2. Проверить резюме и ответить «да» или нажать «Подтвердить и найти». Результаты и оценки совпадают с прежним подбором.
3. «А подешевле?» — Nova уточнит новый потолок бюджета, не изменяя его наугад.
4. «До 800 тысяч, дату оставим» — новое резюме, затем подтверждение и новый поиск.
5. «А на другую дату?» → «15 ноября 2026» — остальные условия сохраняются.
6. «Напиши рецепт борща» или просьба обойти фильтры — краткий возврат к задаче, без вызова matcher.

Можно начать с «Ищу фотографа в Астане» и добавить дату, формат и бюджет позже. Год не угадывается. Несколько дат/городов/категорий, другая валюта и расплывчатый бюджет требуют уточнения. Суммы без указания валюты понимаются как тенге в контексте сервиса. «Язык не важен» снимает предпочтение; язык и часы не обязательны для поиска.

Для нового события нажмите «Новый разговор» — это очищает историю и условия текущей сессии. «Начать заново» в чате сбрасывает условия, сохраняя отображаемый разговор. У каждой выдачи в истории остаются её собственные условия; новая правка не меняет старые карточки.

## Архитектура разговора и границы AI

```text
Streamlit chat → OpenAI: классификация + patch условий + уточнения
              → Python: схема, цитата-основание, типы, обязательные поля
              → резюме → подтверждение пользователем
              → существующий matcher.recommend(Request) без изменений
              → OpenAI: объяснения только отобранных карточек
              → проверка источников и отдельная проверка утверждений
              → карточки; при сбое — исходные объяснения matcher
```

`Conversation` хранится в `st.session_state`: черновик семи полей, нерешённые вопросы, подтверждаемый неизменяемый `Request`, последний результат и история. На диск ничего не записывается. Отображается до 80 сообщений, в модель уходит не более 12 последних принятых реплик вместе с актуальным черновиком; состояние не зависит от обрезки истории. Кэш проверенных объяснений ограничен 20 выдачами и изолирован внутри сессии.

LLM возвращает только изменения, каждое с точной цитатой из текущего сообщения. Контроллер проверяет схему, типы, даты, положительные числа и наличие цитат. Неоднозначность блокирует подтверждение даже при наличии старого значения поля. Новый запрос или правка требует нового подтверждения. Подтверждение одноразовое: перерисовка интерфейса не повторяет поиск. Ни классификатор, ни генератор объяснений не имеют tools, прямого доступа к фильтрам, ключу или файловой системе.

Посторонние, бессмысленные, оскорбительные, опасные сообщения и попытки сменить роль выделяются отдельными намерениями. Явные попытки обхода инструкций дополнительно отсеиваются локально. Такие ходы не изменяют черновик, снимают ожидающее подтверждение и не попадают в последующий контекст LLM; ответ перенаправляет к подбору. Текст выводится без HTML/Markdown. Это многослойная защита, но классификация естественного языка остаётся вероятностной — unit-тесты проверяют маршрутизацию, а `eval_live.py` проверяет фактическое поведение модели на примерах.

После фильтрации LLM получает только подтверждённый запрос и выбранные профили (без полных календарей и истории пользователя). Он не может изменить ID, количество, порядок, оценки, исходы или причины отказа. Для объяснения обязательна дословная цитата описания; затем отдельный LLM-вызов проверяет, что утверждения следуют из фактов. Непроверенные объяснения заменяются исходными детерминированными. Эта проверка снижает риск ошибок текста, но не является формальным доказательством; жёсткие условия всегда определяет Python, независимо от текста объяснения.

Один ход обычно требует одного вызова разбора; успешный подтверждённый поиск — ещё двух вызовов на объяснения и проверку всех карточек одним пакетом. Для NO_MATCH и CATEGORY_NOT_FOUND генерация не нужна: сообщение составляется из исходных причин и предлагает только обсудить изменения, ничего не ослабляя автоматически. Тайм-аут каждого API-вызова — 25 секунд, скрытые повторы отключены. Ошибка API даёт понятное сообщение без сырых исключений; объяснения могут откатиться к фактам, а форма остаётся доступной. Запросы отправляются с `store=False`; локальная история не сохраняется между сессиями.

## Каталог и особенности разбора

Фактическое имя полученного файла — `data/hackathon dataset anonymized .csv` (с пробелами). Файл не изменён. Для другого расположения задать `NOVA_DATASET` перед запуском; поддерживаются CSV и JSON-массив объектов той же схемы.

- 66 уникальных профилей: 53 исходных и 13 синтетических, уже присутствующих в датасете. Дополнительные профили не добавлены.
- В `categories`, `event_formats`, `languages`, `busy_dates` значения разделены `|`. Категорий у профиля может быть несколько. Также поддерживаются JSON-массивы.
- `True`/`False` преобразуются явно: строка `False` не становится истинным значением.
- Девять пустых `max_hours` преобразуются в `None`: ограничение по продолжительности неприменимо. При указанной продолжительности такой профиль не исключается.
- Восемь профилей имеют `city_imputed`, 18 — `price_imputed`. Эти признаки показаны на карточках; восстановленные значения используются как значения каталога.
- Городские значения: Алматы, Астана, Зарубежье. Последнее сохранено как есть; описания не используются для расширения географии.
- Даты занятости: ISO `YYYY-MM-DD`, в предоставленном файле — с 23.09.2026 по 31.12.2026. Отсутствие даты в `busy_dates` означает доступность **по данным каталога**; внешнего подтверждения нет.
- `price_from_kzt` — начальная цена, а не почасовой тариф или окончательная смета. Фильтр сравнивает её с бюджетом, не умножает на часы и не придумывает доплаты. Карточки показывают «от»; точную стоимость из этого датасета установить нельзя.
- Неполные обязательные поля, дубликаты ID, некорректные даты, числа и флаги вызывают понятную ошибку с номером профиля. Некорректные ограничения не заменяются на «свободен» или нулевую цену.

## Пайплайн

`matcher.py` не зависит от Streamlit и не делает сетевых запросов.

1. `filter_candidates`: точное совпадение города и категории после нормализации регистра, пробелов и `ё/е`; затем дата, поддерживаемый формат, начальная цена ≤ бюджет и `max_hours ≥ duration`, если оба значения применимы.
2. `rank_candidates`: вычисляет прозрачные составляющие оценки только для прошедших фильтры кандидатов.
3. `recommend`: сортирует по убыванию полной оценки, затем по строковому ID по возрастанию; округление применяется только после сортировки. Возвращает максимум три карточки. При одинаковом каталоге и запросе результат не зависит от порядка строк, времени или случайности.
4. `explain`: составляет объяснение из имени, города, категории, даты, цены, формата, часов, языка и дословного фрагмента описания. LLM не используется, новые факты не генерируются.

| Сигнал | Баллы | Правило |
| --- | ---: | --- |
| Формат | 20 | У всех прошедших фильтр формат поддерживается; это фиксированная составляющая |
| Язык | 0 или 30 | 30 при совпадении; если предпочтение не задано, 30 у всех |
| Бюджет | 0–15 | `15 × max(0, 1 − abs(цена / бюджет − 0.75) / 0.75)` |
| Продолжительность | 10–15 | `10 + 5 × min((max_hours − часы) / часы, 1)`; при отсутствии ограничения или запроса — 15 |
| Описание | 0–20 | `20 × cosine(TF-IDF(запрос), TF-IDF(описание))` |

Бюджетная составляющая предпочитает начальную цену около 75% бюджета, оставляя резерв. Это демонстрационная эвристика, а не оценка качества услуги: самый дешёвый подрядчик не получает автоматического преимущества. Язык — мягкое предпочтение, несовпадение явно отмечается в объяснении.

TF-IDF рассчитывается по всему каталогу: `idf = log((1 + N) / (1 + df)) + 1`, TF — число вхождений. Запрос состоит из категории, формата и выбранного языка. Токенизация локальная, без стемминга и словаря синонимов: это простая лексическая близость, поэтому разные формы русского слова могут не совпасть. Максимум — 100 баллов; это соответствие запросу, не рейтинг качества подрядчика.

В ответе `recommend` есть `status`, `message`, `cards`, `rejections`, `city_category_count`, `eligible_count`. Карточка содержит объект `Contractor`, `score`, `score_parts`, `explanation`.

- `SUCCESS`: есть подходящие профили; если их меньше трёх, сообщение объясняет это.
- `CATEGORY_NOT_FOUND`: в выбранном городе нет нужной категории.
- `NO_MATCH`: категория в городе есть, но все профили отсеяны. Причины считаются независимо; один профиль может нарушить несколько условий, поэтому сумма причин может превышать число профилей.

## Демонстрация

Во вкладке «Форма и демо» выбрать сценарий над полями формы и нажать **«Найти подрядчиков»**. Значения можно менять; изменение ввода убирает старые результаты формы.

| Сценарий | Город, дата, формат | Категория и условия | Ожидаемый результат |
| --- | --- | --- | --- |
| Сравнение | Алматы, 02.11.2026, свадьба | Ведущий; 2 000 000 ₸; 6 ч; русский | 4 подходят; показаны Сон Гоку, Хаул, Эмилия |
| Редкая категория | Алматы, 14.11.2026, свадьба | Флорист; 400 000 ₸; без часов; русский | 1 карточка: Тихиро Огино, пометка «Синтетический профиль» |
| Нет совпадений | Алматы, 14.11.2026, свадьба | Ведущий; 1 000 ₸; 6 ч; русский | 5 заняты, 4 не поддерживают формат, у 10 начальная цена выше бюджета |
| Нет категории | Астана, 14.11.2026, свадьба | Декоратор; 400 000 ₸ | Категория отсутствует в городе |

В карточках раскройте **«Почему такой порядок результатов»**, чтобы показать составляющие оценки судьям. CLI `demo.py` воспроизводит те же запросы.

## Файлы

- `app.py` — русский интерфейс чата и карточки истории.
- `manual_ui.py` — исходная форма и демо, сохранённые рядом с чатом.
- `conversation.py` — состояние сессии, валидация изменений, подтверждения и маршрутизация.
- `agent_models.py`, `prompts.py` — строгие схемы ответов и промпты.
- `llm_client.py` — серверный адаптер OpenAI и проверка объяснений.
- `matcher.py` — загрузка, валидация, фильтры, TF-IDF, рейтинг, объяснения.
- `demo.py` — путь к каталогу и фиксированные демосценарии.
- `data/` — предоставленный CSV.
- `test_matcher.py` — ограничения, границы, воспроизводимость, парсинг и проверка всех занятых дат каталога.
- `test_app.py` — четыре сценария через Streamlit AppTest, маркировка синтетики, удаление устаревших результатов при изменении ввода.
- `test_conversation.py`, `test_chat_ui.py`, `test_llm_client.py` — разговор, границы API, безопасность, ошибки, состояние, UI и неизменность результатов.
- `eval_live.py` — отдельные проверки реального API: диалог, уточнения, исправления и сообщения вне роли.

Интеграция следует [официальной документации OpenAI по Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). `matcher.py`, CSV, `test_matcher.py` и `test_app.py` при добавлении чата не изменялись.
